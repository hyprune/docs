## Keep the render pass predictable

The plugin reads immutable frame state and draws prepared resources. Capture refresh, cursor changes, focus, workspace transitions and uploads run in a verified safe phase after the outer compositor frame. CPU workers decode assets; they never access compositor objects or GL.

## Rendering on a laptop

The world renders below output resolution and is upscaled with FSR 1; dynamic resolution adjusts the scale in 1/16 steps to hold the frame rate. When nothing in view changes, core re-presents the last world frame instead of rendering a new one. On machines with a discrete GPU, an optional worker supervised by `hypruned` can render the world there and return frames over DMA-BUF, under a power budget and with immediate local fallback. It is off by default ([RFC-0009](/rfcs/0009-offload-renderer/)). Native application windows are always composited locally. The [progress page](/progress/#frame-rate-power-and-memory) has the measurements.

## Honest failure boundaries

A shell crash releases overlay input, and a restarted shell renews its credentials and resyncs from a snapshot. A daemon crash triggers the plugin's desktop recovery watchdog. A malformed world fails staging before activation. Extensions will run as separate supervised processes and can't execute inside the compositor; the host isn't built yet. A plugin bug can still crash Hyprland, which is why that boundary stays small and is tested against an exact compositor build (Hyprland 0.56.2).

## Machine-readable contracts

The schema repository owns the machine-readable definitions. The [schema reference](/reference/schema/) renders every published version of the [world manifest](/reference/schema/world/), [IPC protocol](/reference/schema/ipc/), [input keymap](/reference/schema/input/), [extension manifest](/reference/schema/extension/) and [screen type descriptor](/reference/schema/screen-type/), with diffs between versions and the raw JSON to download. Runtime validation uses pinned local copies, never the network.
